Webots + ROS2 移动机器人导航仿真

一句话成果

基于 ROS2 Humble、Nav2、TurtleBot3 和 Webots/Gazebo 思路，我搭建并整理了一套移动机器人导航仿真流程，用于验证机器人建模、传感器数据流、TF 链路、路径规划和速度控制输出。

项目定位

  • 方向: 机器人导航与控制
  • 工具: ROS2 Humble、Nav2、TurtleBot3、Gazebo/Webots、RViz、SLAM Toolbox
  • 能力展示: 仿真环境搭建、ROS2 节点调试、TF/Topic 证据整理、导航链路拆解
  • GitHub: KITTIYOJIANG/ros2_nav
  • 当前状态: 已补充本地运行证据图；没有找到可用本地工程视频，所以暂不嵌入本地视频，后续可补录完整导航演示

快速入口

  • 代码仓库: github.com/KITTIYOJIANG/ros2_nav
  • 项目总览: 作品集 Portfolio
  • 重点证据: Nav2 lifecycle active、26 nodes、62 topics、导航 goal accepted、1169 条 ROS bag 消息

我的职责

  • 搭建 Webots/Gazebo 仿真环境，配置机器人模型、传感器和运动约束。
  • 整理 ROS2 launch、Nav2 参数、地图、RViz 配置和仿真运行流程。
  • 拆分导航链路中的关键输入输出，包括 /scan、/odom、/tf、/plan 和 /cmd_vel。
  • 用截图、TF 树、topic/node 列表和 ROS bag 记录本地运行证据，便于复现与验收。

系统拆解

  1. 仿真环境: Webots/Gazebo 负责机器人模型、场景、传感器反馈和碰撞环境。
  2. 数据接口: ROS2 topic/service/action 用于传递传感器状态、TF、导航目标和控制指令。
  3. 定位与规划: AMCL、map server、planner server 和 controller server 组成核心导航链路。
  4. 验证方法: 通过 lifecycle 状态、topic 输出、TF 结构、路径规划结果和速度命令验证系统是否跑通。

下一步

  • 视频: 补录机器人从起点到目标点的完整导航演示。
  • 指标: 继续补充路径长度、到达时间、碰撞次数和控制误差等量化数据。
  • 工程整理: 将 Webots 场景、SLAM 建图记录和 Nav2 运行证据进一步统一到同一个 README 结构里。

这个项目想证明什么

招聘方看这个项目时，重点不是“只放一张仿真截图”，而是能看到我在机器人系统里拆问题的方式：环境、数据、定位、规划、控制、验证，每一层都能单独定位问题，也能组合成完整链路。
