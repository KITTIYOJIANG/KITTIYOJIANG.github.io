智能车人工智能视觉组：视觉识别、地图规划与车端控制

一句话成果

面向第二十一届全国大学生智能汽车竞赛人工智能视觉组，我把 FOMO 轻量视觉模型、OpenART/OpenMV 板端识别、16x12 地图建模、BFS/A* 路径规划 与 RT1064 车端通信 串成一条可验证的工程链路，并保留了训练评估、实机识别、地图跟踪和通信联调证据。

项目定位

  • 方向: 嵌入式机器视觉 / 智能车 / 路径规划 / 软硬件联调
  • 工具: Python、OpenART/OpenMV、TensorFlow Lite、FOMO、SmartCar VR、BFS/A*、RT1064、UART/WiFi
  • 能力展示: 数据与模型评估、板端部署、曝光与 ROI 调参、地图抽象、搜索规划、通信协议、测试验证
  • 当前状态: 已完成角色/数字识别录屏、地图定位与角度跟踪、FOMO 评估、规划器与命令消费者，以及 UART/WiFi 联调记录
  • GitHub: KITTIYOJIANG/smCar

系统总览

这个项目不是简单地“让车动起来”，而是把训练、识别、定位、规划和通信拆成可独立验证的工程接口：视觉侧输出角色、数字、地图单元与车辆姿态，规划侧生成动作序列，车端通过串口/WiFi 接收控制请求与结果。

Vision-to-Control 链路

核心链路分为五层：

  1. SmartCar VR 上位机: 提供虚拟推箱子场景、全局视角和第一视角图像。
  2. OpenMV 图像调参: 关闭自动曝光/增益/白平衡，针对屏幕过亮问题动态压曝光。
  3. 地图抽象: 将识别结果映射成 16x12 文本地图，包括墙、车、箱子、目标点和带标签目标。
  4. 任务规划: 使用 BFS/A* 搜索生成栅格动作，并进行死角剪枝和目标匹配校验。
  5. 车端命令: 将路径编译成 move_to、align_to_box、push_box 三类 JSON 指令。

OpenMV 屏幕过曝处理

实际调试时，摄像头看到的屏幕很容易过亮，导致白色路径和青色背景粘在一起。为此我写了一个 OpenMV 脚本，固定手动参数并根据屏幕 ROI 的 LAB 亮度动态压曝光。

我的职责

  • 阅读并整理智能视觉组虚拟推箱子规则，把比赛任务拆成可编码的地图、目标和动作接口。
  • 实现文本地图解析、状态表达、BFS/A* 搜索、死锁判断和路径回放验证。
  • 设计车端 JSON 命令格式，让规划输出可以交给后续底盘控制层执行。
  • 接入官方调试环境资料包，梳理 SmartCar_VR_V1.2、AprilTag、数据集、iVCam 和 spacedesk 的使用步骤。
  • 针对 OpenMV 看到屏幕过亮的问题，编写暗屏调参脚本并给出曝光、增益、亮度、对比度配置。

这个项目想证明什么

这个项目展示的是我把一个“比赛任务”拆成工程系统的能力：先用文本地图和测试集把算法跑通，再定义车端命令边界，最后逐步接入真实视觉和底盘。这样每一层都可以单独验证，现场调试时也更容易定位问题。
