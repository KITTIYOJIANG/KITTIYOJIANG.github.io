智能车人工智能视觉组虚拟推箱子规划

一句话成果

面向第二十一届全国大学生智能汽车竞赛人工智能视觉组，我整理并实现了一条从 OpenMV 屏幕图像调参、16x12 推箱子地图建模、BFS/A* 路径规划 到 车端 JSON 命令输出 的原型链路，用于把虚拟推箱子任务拆成真实小车可以执行的 move_to、align_to_box、push_box 指令。

项目定位

  • 方向: 机器视觉 / 智能车 / 路径规划 / 嵌入式系统
  • 工具: Python、OpenMV、SmartCar VR V1.2、BFS、A*、JSON command interface
  • 能力展示: 比赛规则拆解、视觉调参、地图抽象、搜索规划、指令编译、测试验证
  • 当前状态: 已完成文本地图模拟器、规划器、命令消费者、OpenMV 暗屏调参脚本和官方调试环境接入记录

系统总览

这个项目不是简单地“让车动起来”，而是先把比赛任务拆成可验证的工程接口：视觉侧负责把屏幕里的虚拟场地转成地图，规划侧负责算出推箱子动作，车端只接收压缩后的动作命令。

Vision-to-Control 链路

核心链路分为五层：

  1. SmartCar VR 上位机: 提供虚拟推箱子场景、全局视角和第一视角图像。
  2. OpenMV 图像调参: 关闭自动曝光/增益/白平衡，针对屏幕过亮问题动态压曝光。
  3. 地图抽象: 将识别结果映射成 16x12 文本地图，包括墙、车、箱子、目标点和带标签目标。
  4. 任务规划: 使用 BFS/A* 搜索生成栅格动作，并进行死角剪枝和目标匹配校验。
  5. 车端命令: 将路径编译成 move_to、align_to_box、push_box 三类 JSON 指令。

已完成内容

模块 当前结果
文本地图模拟器 支持固定 16x12 地图、墙体、车、无标签箱子、带标签箱子和目标点
搜索规划 支持 BFS 和 A*，带基础死锁剪枝
命令编译 将栅格路径压缩成实车友好的三类动作
回放验证 对编译后的动作重新 replay，防止路径压缩出错
命令消费者 校验 JSON 指令并分发到底盘控制占位接口
OpenMV 调参 写入暗屏参数脚本，针对屏幕过曝自动降低曝光
调试环境 已接入官方 SmartCar_VR_V1.2、iVCam、spacedesk 和 AprilTag 资料包

OpenMV 屏幕过曝处理

实际调试时，摄像头看到的屏幕很容易过亮，导致白色路径和青色背景粘在一起。为此我写了一个 OpenMV 脚本，固定手动参数并根据屏幕 ROI 的 LAB 亮度动态压曝光。

我的职责

  • 阅读并整理智能视觉组虚拟推箱子规则，把比赛任务拆成可编码的地图、目标和动作接口。
  • 实现文本地图解析、状态表达、BFS/A* 搜索、死锁判断和路径回放验证。
  • 设计车端 JSON 命令格式，让规划输出可以交给后续底盘控制层执行。
  • 接入官方调试环境资料包，梳理 SmartCar_VR_V1.2、AprilTag、数据集、iVCam 和 spacedesk 的使用步骤。
  • 针对 OpenMV 看到屏幕过亮的问题，编写暗屏调参脚本并给出曝光、增益、亮度、对比度配置。

这个项目想证明什么

这个项目展示的是我把一个“比赛任务”拆成工程系统的能力：先用文本地图和测试集把算法跑通，再定义车端命令边界，最后逐步接入真实视觉和底盘。这样每一层都可以单独验证，现场调试时也更容易定位问题。
