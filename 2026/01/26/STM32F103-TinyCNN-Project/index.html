STM32F103 TinyCNN 手写数字识别

一句话成果

在资源受限的 STM32F103C8T6 (Cortex-M3, 72MHz, 无 FPU) 上，我用纯 C 实现了 TinyCNN 的前向推理链路，让单片机可以完成手写数字识别。

核心指标

  • 硬件: STM32F103C8T6 + USB 转 TTL + Python 手写数字画板
  • 模型: PyTorch 训练，2 层卷积 + 1 层全连接
  • 推理耗时: 约 220ms
  • 准确率: MNIST 测试集 >98%
  • 资源占用: Flash < 20KB，RAM < 5KB

Demo

完整演示视频先保留外部平台链接：小红书视频。

我的职责

  • 使用 PyTorch 训练 MNIST TinyCNN，并将权重导出为 C 语言数组。
  • 在 STM32 上手写卷积、ReLU、MaxPool、全连接等基础算子。
  • 设计 Python 上位机画板，通过 UART 将 28x28 图像数据发送给 MCU。
  • 调整内存布局，避免默认栈空间不足导致 HardFault。
  • 通过预处理优化手写输入，使输入分布更接近 MNIST 数据集。

系统架构

  1. 模型训练: PC 端用 PyTorch 完成训练，把权重导出到 weights.h。
  2. 数据通信: Python 上位机通过 UART 115200 baud 发送 784 bytes 图像数据。
  3. 单片机推理: MCU 端运行纯 C 推理引擎，并返回预测类别与推理耗时。
  4. 结果展示: 上位机显示 Predict 和 Time，用于快速验证模型输出。

难点与解决方案

F103 不支持官方 AI 库

问题: STM32F103 是 Cortex-M3 内核，不适合直接套用 X-CUBE-AI。

解决: 自己实现 CNN 前向传播所需算子，并使用静态缓冲区管理中间结果，避免动态内存分配。

栈空间不足

问题: 推理过程中的临时数组容易让默认 1KB 栈空间溢出，程序进入 HardFault。

解决: 调整启动文件中的 Stack_Size 到 0x1000，同时减少临时数组和重复缓冲。

手写输入和 MNIST 分布不一致

问题: 直接缩放用户手写图像时，数字位置和笔画粗细容易偏离训练集分布。

解决: 在 Python 端加入自动居中、二值化和锐化处理，提高实际手写输入的稳定性。
