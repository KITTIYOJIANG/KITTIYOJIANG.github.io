硬核！纯C语言在STM32F103上从零手写卷积神经网络 (TinyCNN)

项目简介 (Project Overview)

在资源极度受限的 STM32F103C8T6 (Cortex-M3, 72MHz, 无FPU) 上，我成功部署了一个手写数字识别系统。

不同于使用 ST 官方的 X-CUBE-AI（F103 不支持）或 MicroPython，本项目从零开始用纯 C 语言实现了卷积神经网络 (CNN) 的底层算子（卷积、池化、全连接），并在单片机上完成了端到端的推理。

核心参数 (Key Specs)

  • 硬件: STM32F103C8T6 + USB转TTL + 自制 Python 画板
  • 模型: PyTorch 训练的 2层卷积 + 1层全连接 TinyCNN
  • 性能: 推理耗时 220ms / 准确率 >98%
  • 资源: Flash占用 <20KB, RAM占用 <5KB (手动优化内存管理)

演示视频 (Demo)

这是实际运行效果。我在电脑端的 Python 画板上手写数字，通过串口实时发送给 STM32，单片机推理完成后返回识别结果。

(或者如果你把视频发到了 Bilibili/YouTube，可以直接贴 iframe 代码)

系统架构 (Architecture)

  1. 模型训练 (Training): 使用 PyTorch 在 PC 端训练 MNIST 数据集，并将权重导出为 C 语言头文件 (weights.h)。
  2. 数据通信 (Communication): Python 上位机通过串口 (UART, 115200 baud) 将 28x28 像素的二值化图像数据 (784 bytes) 发送给 MCU。
  3. 推理引擎 (Inference Engine): 在 MCU 上运行手写的 C 语言推理代码，包含 Conv2d, MaxPool2d, ReLU, FullyConnected 等算子。

遇到的挑战与解决方案 (The “Hard” Parts)

1. F103 不支持 AI 库

问题: STM32F103 是老款 Cortex-M3 内核，不支持 ST 的 X-CUBE-AI 扩展包。
解决: 手写算子。我复现了深度学习的前向传播过程。为了节省内存，我没有使用动态内存分配 (malloc)，而是使用了静态全局缓冲 (Static Buffers) 并复用内存块。

2. 栈溢出 (Stack Overflow)

问题: 神经网络推理过程中产生的临时数组会导致 1KB 的默认栈空间瞬间爆炸，程序进入 HardFault。
解决: 修改启动文件 startup_stm32f103xb.s，将栈空间 (Stack_Size) 调整为 **4KB (0x1000)**，确保了系统的稳定性。

3. 通信与数据预处理

问题: 简单的图像缩放会导致识别率低。
解决: 在 Python 端增加了自动居中 (Auto-centering) 和 二值化锐化 算法，模拟 MNIST 数据集的格式，显著提升了“潦草字迹”的识别率。

当自动化遇到 AI：为什么我们需要从 PID 走向强化学习？

摘要：作为一个自动化专业的学生，PID 是我最熟悉的“老朋友”。但在面对具身智能（Embodied AI）中复杂的非结构化环境时，这位老朋友似乎开始力不从心。本文将从我的视角出发，探讨为什么强化学习（RL）是下一代机器人控制的必经之路。

这里的“舒适区”：经典的 PID 控制

在自动化专业的课本里，PID（比例-积分-微分）是绝对的王者。无论是控制四轴飞行器的姿态，还是调节恒温箱的温度，PID 都能以其优雅的数学形式（$u(t) = K_p e(t) + K_i \int e(t) dt + K_d \frac{de(t)}{dt}$）解决问题。

它的核心逻辑是 “基于误差的反馈消除”。只要我们能建立准确的数学模型（Transfer Function），通过根轨迹法或伯德图整定参数，系统就能稳如泰山。

但是，现实世界往往不讲“武德”。

挑战：当环境变得不可预测

当我们试图让机器人走出工厂的围栏，进入家庭或野外时，经典控制理论遇到了三大挑战：

  1. 无法建模的复杂性：你很难为一件刚洗完的衣服（柔软、形变）建立精确的动力学模型。
  2. 非结构化环境：家里的椅子可能被挪动了，地面可能有水渍。PID 很难处理这种突发的“干扰”。
  3. 多模态感知：经典控制通常输入是传感器数值（如角度、速度），但现代机器人需要“看”图（视觉输入）。设计一个从像素直接到电机力矩的 PID 控制器几乎是不可能的。

破局：强化学习 (RL) 的思维转换

强化学习（Reinforcement Learning）带来了一种全新的思维方式：不再通过人工推导公式来告诉机器人“怎么走”，而是通过奖励函数（Reward Function）告诉它“做得对不对”。

一个直观的对比

  • PID 思维：如果是倒立摆，我会计算角度偏差，根据公式算出反向力矩。
  • RL 思维：我给机器人一个环境。如果杆子掉下来了，扣 10 分；如果坚持了 1 秒，加 1 分。让它自己在几万次尝试中“顿悟”出力矩与角度的关系。

为什么选择 RL？

  1. **端到端学习 (End-to-End)**：RL 可以直接将摄像头的 RGB 图像作为输入，输出关节的电机指令，跳过了繁琐的特征提取和状态估计环节。
  2. **适应性 (Generalization)**：通过在仿真环境中引入“域随机化”（Domain Randomization），比如随机改变摩擦力、光照、物体质量，训练出的策略可以适应真实世界中的各种不确定性。这正是 Sim-to-Real 的核心魅力。

我的下一步：从理论到代码

理解原理只是第一步。在接下来的几周里，我计划：

  1. 复现经典：在 OpenAI Gym 环境中，用 DQN 或 PPO 算法跑通 CartPole（倒立摆）任务。
  2. 仿真进阶：使用 NVIDIA Isaac Sim 搭建一个简单的机械臂抓取场景。
  3. 对比实验：尝试分别用 PID 和 RL 解决同一个控制问题，亲身体会两者的边界。

结语：自动化赋予了我理解物理世界的严谨逻辑，而 AI 则赋予了机器适应未知的灵性。两者的结合，或许就是通往通用机器人（AGI）的钥匙。
